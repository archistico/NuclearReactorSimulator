# M10.9.8 — Integrated Human-Automation-HMI Validation Gate — PLAN

**Status:** PLANNED — prerequisite M10.9.7 VALIDATED.

## Goal

Close M10 by validating the complete operator experience as one system rather than validating another feature in isolation.

No new feature should normally be introduced in M10.9.8. It is an integration/acceptance milestone.

## Fixed axes

### Training assistance

- `Hidden`;
- `ChecklistOnly`;
- `Guided`.

### Plant control authority

- `Manual`;
- `Assisted`;
- `SupervisoryAutomatic` requested/effective semantics.

The basic matrix is therefore 3 × 3 = 9 requested-mode combinations, plus degraded effective-authority cases where supervisory control must fail closed to Assisted.

## M10.9.8.1 — Freeze validation matrix and invariants

Before running implementation changes, freeze the matrix rows and expected invariants.

Minimum scenario families:

1. healthy steady operation / bounded load change;
2. synchronization and loading;
3. command blocked by a real permissive/interlock;
4. invalid/degraded measurement affecting supervisory authority;
5. canonical protection trip;
6. supported injected equipment/instrument fault;
7. manual takeover from supervisory operation;
8. challenge/demand-following exercise;
9. checkpoint/replay continuation.

## Cross-cutting invariants

For every applicable row:

- changing training assistance alone must not change plant physics/control authority;
- protection always overrides manual/assisted/supervisory normal control;
- requested and effective authority remain visibly distinct;
- supervisory degradation is fail-closed and evidence-based;
- command-consequence expected influence remains separate from observed response;
- challenge demand remains separate from requested load and actual output;
- scoring remains observational;
- unavailable/suspect measurements remain visibly unavailable/suspect;
- replay/checkpoint reproduces the same deterministic state, score and presentation;
- keyboard-only operation remains viable.

## M10.9.8.2 — Automated assistance × authority matrix

Run all nine requested-mode combinations over a bounded healthy scenario and representative command/challenge actions.

### Acceptance

- same physical initial condition and same physical commands produce equivalent plant results where authority semantics are equivalent;
- assistance-only changes affect guidance presentation, not plant state;
- authority changes alter only the already-defined M5 control seams;
- no hidden score/control coupling exists.

## M10.9.8.3 — Degraded/fault/protection/takeover cases

Exercise:

- invalid required measurement;
- protection active;
- supported component/instrument fault;
- rejected command/permissive failure;
- requested supervisory authority becoming effectively Assisted;
- operator manual takeover.

### Acceptance

- degradation reason is explicit;
- takeover is bumpless under existing M5 contracts;
- protection cannot be bypassed by assistance/challenge/workstation state;
- command consequence and mission workstation both show canonical degraded truth.

## M10.9.8.4 — Replay/checkpoint/same-seed integrity

For selected matrix rows verify:

- full trace replay equivalence;
- checkpoint prefix + continuation equivalence;
- challenge/demand/score equivalence;
- command-consequence observed-response equivalence;
- authority/guidance transition equivalence;
- deterministic fingerprints where already part of project validation practice.

## M10.9.8.5 — Manual HMI acceptance and M10 closure

Manual acceptance must cover at least:

- minimum supported window size;
- keyboard-only navigation and command execution;
- PLANT + subsystem mimic/schematic readability;
- advanced gauges and provenance;
- alarm/protection prominence;
- consequence explanation and schematic highlighting;
- mission/performance workstation;
- assistance and authority state clarity;
- replay/session workflow.

## Failure discipline

M10.9.8 failures are classified before any fix:

- presentation/usability defect → fix in HMI/application projection;
- deterministic/replay defect → fix in existing replay/session owner;
- challenge/scoring defect → return only to M10.9.6 owner;
- authority defect → return only to M5-defined owner;
- newly discovered physical-model defect → record as post-M11 engineering issue unless it makes current validated M10 operation unsafe/unusable.

Do not use M10.9.8 as an excuse to reopen numerical Phase H/I tuning without direct evidence.

## Exit condition — M10 complete

M10 is closed only when:

- build and complete ordinary suite are green;
- automated M10.9.8 matrix is green;
- replay/checkpoint integrity is green;
- manual HMI acceptance is explicitly confirmed;
- `KNOWN_MODEL_LIMITATIONS.md`, user manual and current project documentation reflect the validated product state.

Only then start M11.
