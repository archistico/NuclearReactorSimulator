# M10.9.8 — Integrated Human-Automation-HMI Validation Gate — DETAILED PLAN

**Status:** PLANNED — prerequisite M10.9.7 closed.  
**Detailed cross-milestone execution map:** [`../FORWARD_EXECUTION_PLAN_M10_9_7_TO_M15.md`](../FORWARD_EXECUTION_PLAN_M10_9_7_TO_M15.md).

## Goal

Validate M10 as one coherent operator system across training assistance, plant control authority, faults, protection, challenge/scoring, replay/session and manual operation. M10.9.8 is an integration/acceptance milestone, not a feature milestone.

## No-feature rule

A failing matrix row must first be classified by owner. M10.9.8 must not become an excuse to invent new physics, retune Phase H/I numerics or add new HMI features that were not required by an acceptance defect.

## Fixed axes

### Training assistance

- `Hidden`;
- `ChecklistOnly`;
- `Guided`.

### Plant control authority

- `Manual`;
- `Assisted`;
- `SupervisoryAutomatic` requested/effective semantics.

The healthy requested-mode matrix is 3 × 3 = 9 combinations, augmented by degraded cases where effective authority intentionally differs from requested authority.

---

## M10.9.8.1 — Freeze validation matrix and invariants

### Matrix row contract

Each row must record:

- stable row ID;
- exact scenario/profile/version;
- deterministic seed if applicable;
- requested assistance mode;
- requested authority;
- expected effective authority;
- initial plant state/profile;
- commands/actions exercised;
- expected challenge/demand profile if any;
- expected protection/fault involvement;
- replay/checkpoint requirement;
- expected mission/computer/alarm evidence;
- manual HMI observations required;
- owner to investigate if the row fails.

### Minimum scenario families

1. healthy steady operation / bounded load change;
2. synchronization and loading;
3. command blocked by real permissive/interlock;
4. invalid/degraded measurement affecting supervisory authority;
5. canonical protection trip;
6. supported injected equipment fault;
7. supported instrumentation fault;
8. manual takeover from supervisory operation;
9. challenge/demand-following exercise;
10. checkpoint/replay continuation;
11. completed/failed mission with plant continuing after terminal step.

### Cross-cutting invariants

For every applicable row:

- changing training assistance alone must not change plant physics/control authority;
- protection always overrides normal control;
- requested and effective authority remain visibly distinct;
- supervisory degradation is fail-closed and evidence-based;
- expected command influence remains separate from observed response;
- external demand remains separate from requested load and actual output;
- scoring remains observational;
- unavailable/suspect measurements remain unavailable/suspect;
- MISSION has no plant-command authority;
- replay/checkpoint reconstructs equivalent operator-visible state;
- keyboard-only operation remains viable.

### Deliverable

A frozen machine-readable matrix and human-readable matrix explanation. No repairs begin until this contract is accepted.

## M10.9.8.2 — Automated assistance × authority matrix

### Healthy matrix

Run all 9 requested combinations on the same bounded healthy trajectory and representative command sequence.

### Compare

- physical plant fingerprints/selected canonical state;
- requested/effective authority;
- assistance/guidance presentation;
- command acceptance/rejection;
- challenge lifecycle/demand/score;
- MISSION presentation;
- alarm/protection state;
- replay fingerprint where already available.

### Acceptance

- assistance-only changes affect guidance, not physical state;
- equivalent effective-authority semantics produce equivalent physical results;
- authority transitions use only established M5 seams;
- no score changes merely because guidance is more/less visible unless a versioned policy explicitly owns that effect;
- demand never writes requested generator load.

---

## M10.9.8.3 — Degraded measurement / fault / protection / takeover matrix

### Required cases

- invalid required supervisory measurement;
- suspect/unavailable measurement shown to operator;
- protection active before normal command;
- protection trip during automated/assisted operation;
- component fault;
- instrumentation fault;
- command rejected by permissive/interlock;
- requested SupervisoryAutomatic degrading to effective Assisted;
- operator manual takeover;
- supported recovery/reset sequence;
- challenge active during degraded/protection state.

### Acceptance per row

- degradation reason explicit;
- requested/effective authority distinction correct;
- takeover bumpless under existing control contracts;
- protection cannot be bypassed by assistance, challenge or HMI;
- command consequence and MISSION show the same canonical degraded truth;
- faults remain fault-framework owned;
- no hidden UI fallback writes plant state.

---

## M10.9.8.4 — Replay/checkpoint/same-seed integrity

For representative healthy and degraded rows verify:

- full replay canonical equivalence;
- checkpoint prefix + continuation equivalence;
- challenge lifecycle/demand/score equivalence;
- MISSION snapshot/timeline equivalence;
- command consequence observed-response equivalence;
- requested/effective authority transition equivalence;
- alarm/protection presentation equivalence;
- deterministic fingerprints where established.

### Important rule

No opaque workstation state dump is allowed to become necessary to reproduce MISSION/COMPUTER presentation. State should be canonical, derivable or explicitly versioned at the correct Application owner.

## M10.9.8.5 — Manual HMI acceptance and M10 closure

### Manual route

Perform an end-to-end operator session covering:

- minimum supported window size;
- keyboard-only workspace navigation;
- PLANT overview and subsystem workspaces;
- COMPUTER F1–F8;
- MISSION workspace;
- command consequence/context inspector;
- alarms/protection/first-out visibility;
- assistance mode changes;
- requested/effective authority changes;
- fault/degraded measurement presentation;
- save/session/checkpoint/replay;
- mission timeline/drill-down.

### Visual acceptance

- protection/safety cannot be visually overshadowed by score;
- unavailable/suspect values are obvious;
- demand/request/actual distinction is obvious;
- no internal milestone labels leak into operator UI;
- keyboard focus is visible;
- all critical actions have clear feedback.

### Closure artifacts

Produce:

- matrix summary;
- failed-row classification report if any;
- replay/checkpoint equivalence summary;
- manual HMI checklist;
- M10 closure summary;
- updated known limitations/user manual references.

## Failure classification discipline

- presentation/usability defect → HMI/Application presentation owner;
- deterministic/replay defect → existing recorder/session owner;
- challenge/scoring defect → M10.9.6 owner;
- authority defect → M5 owner;
- newly discovered physical-model defect → post-M11 engineering backlog unless it invalidates current supported operation;
- numerical Phase H/I issue → reopen only with direct evidence against a validated numerical contract.

## Exit condition — M10 complete

M10 is closed only when:

- build and complete ordinary suite are green;
- automated matrix is green;
- replay/checkpoint integrity is green;
- manual HMI acceptance is explicitly confirmed;
- `KNOWN_MODEL_LIMITATIONS.md`, manual and project documentation reflect the validated product state.

Only then start M11.
