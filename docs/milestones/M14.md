# M14 — Spatial Reactor — DETAILED PLAN

**Strategic epic:** Epic B — Spatial Reactor.  
**Status:** PLANNED — prerequisite M13 closed.  
**Detailed cross-milestone execution map:** [`../FORWARD_EXECUTION_PLAN_M10_9_7_TO_M15.md`](../FORWARD_EXECUTION_PLAN_M10_9_7_TO_M15.md).

**Cross-milestone execution discipline:** [`../POST_M10_TO_M15_EXECUTION_MASTER_PLAN.md`](../POST_M10_TO_M15_EXECUTION_MASTER_PLAN.md) and [`../CHANGE_IMPACT_REVALIDATION_POLICY.md`](../CHANGE_IMPACT_REVALIDATION_POLICY.md).

## Goal

Evolve the reference plant from an aggregated visual core toward a deterministic quasi-spatial 2D educational reactor model with multiple zones/equivalent channel groups, explicit rod mapping and selectable local evidence layers, without implying licensing-grade full-channel neutron transport.

## Fidelity boundary

M14 is a reduced-order spatial model. Documentation and UI must say when values are zone/group equivalents rather than individual physical-channel solutions. No feature may imply that every physical RBMK channel is being solved independently unless the model actually does that.

## Cross-cutting requirements

- deterministic stable zone/group IDs and ordering;
- aggregate whole-core consistency;
- no UI-authored physics mapping;
- replay/checkpoint exactness for spatial state;
- bounded 10 ms performance cost;
- explicit provenance for derived/projected spatial fields;
- local damage overlays remain disabled until M15 owns damage.

---

## M14.1 — Quasi-spatial contract and limits

### Freeze before implementation

Define:

- spatial grid/zone count philosophy;
- zone and equivalent-channel-group IDs;
- deterministic 2D coordinates or adjacency map;
- aggregation weights;
- mapping from channel groups to zones;
- mapping from rods/rod groups to zones;
- mapping from instrumentation/evidence to zones;
- whole-core aggregation equations;
- supported local feedback semantics;
- explicit unsupported claims.

### Key design decision

Choose the smallest spatial resolution that materially improves education/gameplay. More zones are not automatically better if they only multiply cost without adding supported physics.

### Tests

- stable ordering independent of dictionary/hash iteration;
- mapping completeness;
- no duplicate IDs;
- aggregate weights normalize correctly;
- deterministic same-definition fingerprint.

---

## M14.2 — Multi-zone/equivalent-channel-group reference core

### Purpose

Make the reference plant genuinely contain multiple spatially identified reduced-order groups.

### Work

- version the reference-plant exact identity rather than reinterpret an old exact version;
- define zone/group composition and canonical IDs;
- distribute whole-core flow/inventory/thermal/power contributions consistently;
- preserve canonical aggregate state owners;
- define initialization for steady reference states.

### Aggregate invariants

At every qualified state:

- zone/group power aggregates to whole-core power within defined tolerance;
- zone/group mass/inventory aggregates consistently;
- flow totals match canonical network ownership;
- no hidden energy source appears from spatial decomposition.

### Qualification

Run representative steady and transient cases and compare aggregate behavior with the pre-spatial reference contract. Expected differences must be versioned and explained.

---

## M14.3 — Multiple rods / rod groups and zone mapping

### Purpose

Replace a visually aggregated rod concept with explicit multiple rod/group identities and deterministic spatial influence.

### Contract

Each rod/group needs:

- stable ID;
- physical/educational group label;
- current position;
- requested target where applicable;
- movement/state semantics from existing actuator ownership;
- zone influence weights/mapping;
- command grouping/selection semantics.

### Constraints

- rod commands remain canonical typed commands;
- spatial mapping lives in definitions/model, not XAML;
- do not invent local kinetics fidelity beyond the chosen reduced-order model;
- maintain protection/SCRAM authority.

### Tests

- command affects intended rod/group identity;
- mapping weights stable;
- aggregate reactivity effect remains consistent;
- replay/checkpoint retains rod/group positions and spatial evidence.

## M14.4 — Local/quasi-spatial feedback and evidence

### Purpose

Expose local variation where the model can justify it.

### Field ownership table

For each candidate field classify it as:

```text
INDEPENDENT_DYNAMIC_STATE
DERIVED_FROM_LOCAL_STATE
WEIGHTED_PROJECTION_FROM_GLOBAL_STATE
UNAVAILABLE
```

Candidate fields:

- local/equivalent power;
- coolant flow;
- void fraction;
- temperature;
- iodine/xenon;
- rod influence;
- instrumentation quality where spatially meaningful.

### Rules

- projection formulas are documented;
- aggregate consistency is tested;
- unavailable local physics stays unavailable rather than being filled with plausible-looking numbers;
- feedback into global kinetics is introduced only through an explicitly reviewed coupling contract.

### Performance

Measure per-step cost before increasing zone count or feedback complexity.

## M14.5 — 2D core map and selectable layers

### UI layers

- POWER;
- FLOW;
- VOID;
- TEMPERATURE;
- XENON;
- ROD POSITION / INFLUENCE.

### Presentation requirements

- clear legend and units;
- absolute vs normalized scale explicitly labeled;
- unavailable/suspect values distinct;
- selected zone outlined/textually identified;
- color not the only carrier of information;
- no smoothing/interpolation that suggests unsupported fine spatial resolution;
- all rendering consumes canonical snapshots.

### Interaction

- keyboard-selectable zones/groups;
- mouse selection;
- layer switching without changing plant state;
- consistent selection shared with drill-down/trends.

---

## M14.6 — Local drill-down and trends

### Selected-zone panel

Expose:

- zone/group identity;
- current local values;
- contribution to aggregate power/flow where meaningful;
- related rod/groups;
- local trend series;
- related alarms/protection/evidence only where canonical mapping exists;
- fidelity/provenance indicator for derived vs independent values.

### Trend contract

Use logical-step time and bounded history. Do not create an unbounded UI history owner.

### Drill-down

Navigation may connect to reactor controls, alarms/events or procedures but cannot issue commands merely by selecting a zone.

---

## M14.7 — Spatial closure gate

### Automated

- same-seed deterministic spatial identity;
- full replay equivalence;
- checkpoint continuation equivalence;
- aggregate conservation/consistency;
- rod/group mapping integrity;
- no unsupported local values fabricated;
- bounded performance/allocation cost;
- ordinary suite.

### Manual

- map readable at minimum window;
- layer legends/units clear;
- reduced-order fidelity clearly communicated;
- no visual implication of full channel-by-channel neutron transport;
- zone selection/drill-down/trends usable.

### Exit condition

M14 closes with a validated quasi-spatial reactor suitable for M15 localized consequence evidence, but with damage overlays still disabled until physical damage owners exist.
