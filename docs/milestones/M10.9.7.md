# M10.9.7 — Mission & Performance Workstation — PLAN

**Status:** PLANNED — prerequisite M10.9.6 VALIDATED.

## Goal

Provide an operator/training workstation that makes the M10.9.6 mission, external demand, progress, score and deterministic history understandable without owning any of those semantics.

## Architectural rule

M10.9.7 is presentation/application aggregation only. Challenge lifecycle, demand timeline and scoring truth remain owned by M10.9.6 contracts.

## M10.9.7.1 — Immutable presentation contract

Project a single mission/performance snapshot containing, when available:

- active mission/challenge identity and objective;
- current phase/status;
- elapsed logical simulation time and target/window;
- external demand;
- requested generator load;
- actual electrical output;
- demand error;
- overall score/classification;
- score dimension decomposition;
- recent objective/protection/scoring events;
- assistance mode and requested/effective control authority.

Unavailable data remains explicitly unavailable.

### Acceptance

- projection contains no scoring formulas;
- values are derived from canonical owners;
- same canonical state produces deterministic presentation output.

## M10.9.7.2 — Workstation placement/navigation decision

The existing Operator Computer has a validated fixed F1–F8 contract. Do **not** add F9 implicitly.

### Recommended plan

Create a dedicated Mission/Performance workspace in the main HMI shell, linked contextually from COMPUTER, while keeping the existing F1–F8 computer menu unchanged. Existing pages may show a compact mission summary and an explicit navigation action to the workstation.

### Decision required before implementation

Confirm one of these options:

- **A — recommended:** dedicated main-HMI workspace, F1–F8 unchanged;
- **B:** deliberately revise the Operator Computer navigation contract and accept a broader M10.8/M10.9 regression surface.

No implementation starts until this is explicitly decided.

## M10.9.7.3 — Objective/demand/progress/score UI

The workstation should answer, at a glance:

1. What am I trying to achieve?
2. What is the external demand now?
3. What load have I requested?
4. What is the plant actually producing?
5. How far am I from the target?
6. What safety/procedure/stability conditions are affecting my result?
7. What should I inspect next?

Use progressive disclosure rather than one dense dashboard.

### Acceptance

- demand/request/actual are never merged into one gauge/value;
- safety/protection significance remains visually dominant over score decoration;
- score decomposition remains understandable without color alone;
- no milestone/internal engineering labels leak into normal operator presentation.

## M10.9.7.4 — Deterministic performance timeline and drill-down

Provide a bounded logical-step timeline for mission events such as:

- objective/phase transition;
- demand change;
- key operator action;
- protection/alarm event relevant to scoring;
- score-dimension change;
- challenge completion/failure/protected-boundary classification.

Timeline ordering must reuse deterministic logical step/event sequence semantics. Wall clock may be displayed only as non-authoritative session metadata if already available; it may not order or score events.

Drill-down may navigate to the relevant subsystem schematic, command consequence or existing alarm/log evidence without mutating plant state.

## M10.9.7.5 — Closure gate

### Automated

- mission/performance projection fidelity;
- deterministic timeline ordering;
- demand/request/actual semantic separation;
- score decomposition equals M10.9.6 owner output;
- navigation has no plant-state side effects;
- reset/replay/checkpoint rebuilds identical workstation state;
- existing M10.8 F1–F8 contract remains green unless option B was explicitly approved.

### Manual

- readable at minimum supported window size;
- keyboard-only navigation practical;
- objective, demand and score can be understood without opening logs;
- protection/safety state cannot be visually overshadowed by “game score” presentation;
- drill-down returns the operator to useful plant evidence.

## Explicit non-scope

- new scoring rules;
- new challenge definitions;
- new plant control authority;
- automatic mission execution;
- wall-clock competitive leaderboards;
- cloud/account/online leaderboard services.

## Exit condition

M10.9.7 becomes VALIDATED only after build, ordinary suite, focused presentation/replay gate and explicit manual HMI confirmation. Only then begin M10.9.8.
