## Planned post-REV2 hardening — M10.9.7.3 Hotfix 2 — Desktop Host Failure & Session Save Integrity

This hotfix is a **precondition for M10.9.7.4**, but it must not be stacked on an unvalidated REV2 candidate. Complete the existing REV2 manual HMI checklist first; only if REV2 is promoted may Hotfix 2 be built on that validated baseline.

### Purpose

Close two desktop-host integrity gaps discovered by the post-7.3 App review without changing Mission/Performance semantics:

1. expected deterministic numerical step failures must become PAUSE + operator-visible diagnostic rather than unhandled Avalonia exceptions;
2. saving over an existing session archive must preserve the prior valid file until the replacement has been written successfully.

### Implementation slices

#### H2-A — Desktop deterministic-step failure boundary

- classify expected host-visible numerical/step failures instead of catching only `InvalidOperationException`;
- include `ArithmeticException` and therefore `OverflowException` where raised by expected fail-closed numerical guards;
- pause through the existing coordinator/runtime command boundary;
- report one clear failure status and avoid repeated timer exception storms;
- do not use blanket exception swallowing for programming defects.

#### H2-B — Session command-handler policy alignment

- protect start-recorded-session and reset/recreate-session boundaries;
- align load and restore failure handling where they traverse equivalent archive/reconstruction contracts;
- centralize classification/message policy sufficiently that equivalent failures cannot drift into four unrelated catch lists.

#### H2-C — Atomic/non-destructive desktop save

- show the destination picker before archive export;
- cancel -> no full archive serialization;
- move write/replace mechanics out of the click handler;
- for local desktop filesystem destinations, write a unique temporary sibling, flush/close it, then replace/move into the destination;
- preserve the previous destination byte-for-byte on write/flush/replace failure;
- cleanup temporary files best-effort;
- if the provider cannot expose safe replacement semantics, fail closed with truthful status rather than truncating first.

Do not move `ExportSessionArchive()` to `Task.Run` until an immutable capture/ownership contract exists; avoiding a UI freeze must not introduce a race with the live session.

#### H2-D — Engineering-number formatting consistency

Align the remaining App-only gauge-scale and COMPUTER setpoint formatting to the current invariant technical HMI convention. Full localization remains a separate presentation policy decision.

#### H2-E — Gate

Planned focused gate:

`scripts/run-m10973-desktop-host-session-integrity-audit.cmd`

Required evidence includes:

- injected expected arithmetic/overflow step failure -> PAUSED + one diagnostic + no unhandled UI exception;
- programming/unclassified exception is not silently swallowed;
- start/reset/load/restore failure boundaries behave consistently;
- picker cancel performs no archive export;
- successful overwrite produces a loadable archive;
- injected write and replace failures preserve the previous archive byte-for-byte;
- temporary cleanup attempted;
- unsupported safe-replace provider fails closed;
- invariant engineering-number presentation contract;
- existing MISSION F1-F8/no-F9/no-command-authority contracts remain green.

### Non-scope

No worker-thread Simulation migration, timestep/solver change, simulation-speed feature, MainWindowViewModel decomposition, archive schema change, streaming persistence or command-target selection refactor belongs to Hotfix 2.

See [`../DESKTOP_HOST_FAILURE_AND_SESSION_SAVE_INTEGRITY_REVIEW.md`](../DESKTOP_HOST_FAILURE_AND_SESSION_SAVE_INTEGRITY_REVIEW.md) and ADR-0185.

## M10.9.7.4 — Deterministic performance timeline and drill-down

Provide a bounded logical-step timeline for mission events such as:

- objective/phase transition;
- demand change;
- key operator action;
- protection/alarm event relevant to scoring;
- score-dimension change;
- challenge completion/failure/protected-boundary classification.

Timeline ordering must reuse deterministic logical step/event sequence semantics. Wall clock may be displayed only as non-authoritative session metadata if already available; it may not order or score events.

Drill-down may navigate to the relevant subsystem schematic, command consequence or existing alarm/log evidence without mutating plant state.

### Detailed implementation slices for M10.9.7.4

#### 7.4-A — Fingerprint-v1 schema anchor

Before extending archive/replay-equivalence presentation work, freeze a populated canonical `ControlRoomSnapshotFingerprint` v1 fixture. Assert the exact `sha256-control-room-snapshot-v1` algorithm id and exact expected 64-hex hash. The fixture must populate every fingerprint-relevant scalar and representative collection element so DTO/snapshot-shape drift cannot silently redefine v1. An intentional semantic change requires a new algorithm id; updating the golden hash without that decision is forbidden.

#### 7.4-B — Lifecycle-spine and recent-evidence retention contract

Do not promote the M10.9.7.3 combined last-100 `RecentEvents` list into the full timeline owner. Define two separately bounded derived presentation sources:

- a protected mission lifecycle spine for activation, terminal completion/failure and relevant reset/restart boundaries;
- bounded recent operational evidence for protection, scoring, operator-action and other event detail.

Dense protection/scoring evidence may evict other recent operational rows but must not erase the mission-defining spine. Neither source is a second recorder.

#### 7.4-C — Timeline projection contract

Create a bounded Application read model over canonical recorder/challenge evidence and merge the two retention sources. Stable order is logical step first, canonical source sequence second, with stable event/source tie-breakers only when required.

#### 7.4-D — Timeline presentation

Show logical step/time, category, concise evidence summary and optional score/source context. Distinguish lifecycle/objective, operator action, protection and scoring evidence visually and textually.

#### 7.4-E — Drill-down target contract

Timeline rows may carry presentation navigation targets to subsystem workspaces, alarms/events or COMPUTER consequence/context evidence. Missing targets degrade to generic evidence rather than failing or issuing a command.

#### 7.4-F — Replay/checkpoint/archive-restored equivalence

Qualify uninterrupted vs replay, checkpoint seek/resume, archive-restored exact mission binding, terminal-challenge/continuing-plant behavior, duplicate suppression and deterministic retained-timeline identity. Replay/seek evidence must continue to declare/verify its fingerprint algorithm explicitly.

#### 7.4-G — Gate

Automated golden-fingerprint, retention, timeline/replay/navigation assertions plus a manual drill-down/back-navigation review.
