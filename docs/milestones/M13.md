# M13 — Control-Room Experience — DETAILED PLAN

**Strategic epic:** Epic C — Control-Room Experience.  
**Status:** PLANNED — prerequisite M12 closed.  
**Detailed cross-milestone execution map:** [`../FORWARD_EXECUTION_PLAN_M10_9_7_TO_M15.md`](../FORWARD_EXECUTION_PLAN_M10_9_7_TO_M15.md).

## Goal

Make the simulator feel and operate more like a coherent industrial control room while preserving the existing subsystem/workspace architecture, canonical command boundaries and strict separation between presentation and plant physics.

## Fixed principles

- keep area/subsystem workspaces; no giant all-controls page;
- Avalonia/IndustrialControls remain presentation adapters only;
- multi-monitor/multi-computer operation remains deferred;
- presets change presentation only;
- mimic layout changes never alter plant topology;
- Instructor/Fault authority may invoke only mechanisms actually modeled at that milestone;
- keyboard operation remains first-class;
- presentation state that must survive save/reload is versioned explicitly rather than hidden in control instances.

## M13.1 — Industrial presentation boundary and visual identity

### Purpose

Strengthen the retro-industrial identity and consistency without moving simulation/control semantics into UI widgets.

### Audit

Inventory current custom controls:

- gauges/meters;
- indicator lamps;
- pushbuttons;
- selectors/toggles;
- trend scopes;
- alarm banners;
- mimic/schematic symbols;
- panel headers/status strips.

For each candidate `archistico/IndustrialControls` control decide:

```text
ADOPT
WRAP
KEEP_EXISTING
REJECT
```

with rationale.

### Acceptance criteria per control

- correct keyboard/focus semantics;
- disabled/unavailable/suspect states;
- no hidden business logic;
- no direct runtime/engine dependency;
- minimum-size readability;
- unit/value formatting consistent with existing snapshots;
- alarms/protection remain more salient than decorative styling.

### Deliverables

- control adoption matrix;
- updated HMI visual design system;
- presentation-component tests where practical;
- focused screenshot/manual review checklist.

## M13.2 — Maintained operator-handle/selector semantics

### Purpose

Represent operator handle position separately from effective equipment state where the physical/control semantics require it.

### Control classes to classify

Every control should be classified as one of:

- momentary pushbutton;
- spring-return command handle;
- maintained selector;
- maintained analog demand/setpoint;
- breaker CLOSE/TRIP style action;
- reset/acknowledge action;
- grouped rod target/demand control.

### Contract

Where maintained state exists, expose separately:

```text
RequestedHandlePosition
EffectiveEquipmentState
Interlock/ProtectionOverrideState
Feedback/IndicationState
```

Do not infer handle position from equipment feedback.

### Persistence/replay

If maintained operator state affects subsequent behavior, it must be part of deterministic command/session/replay evidence rather than transient Avalonia state.

### Tests

- handle remains in requested position while interlock blocks effect, if that is the modeled semantics;
- protection override changes effective equipment state without silently moving the handle unless real semantics demand it;
- replay restores maintained operator state;
- keyboard/mouse paths dispatch the same canonical intent.

## M13.3 — First-class mimic viewport

### Purpose

Turn plant/subsystem mimic diagrams into navigable engineering surfaces rather than static illustrations.

### Features

- zoom around pointer or keyboard focus;
- pan by drag and keyboard-accessible alternative;
- fit-to-view;
- reset view;
- stable equipment selection;
- clear selected-element state;
- drill-down to subsystem/workspace;
- preserve selection where navigation context permits.

### Constraints

- viewport transform is presentation-only;
- no equipment coordinates in Domain/Simulation are mutated;
- alarms and key measurements remain legible at operational zoom levels;
- excessive zoom must not imply geometric precision unsupported by the schematic.

### Tests/manual gate

- deterministic viewport reset;
- selection survives benign snapshot refresh;
- no control command is triggered by pan/zoom gestures;
- minimum-window usability;
- keyboard path to fit/reset/selection.

## M13.4 — Versioned persistent mimic layout

### Purpose

Allow users to arrange mimic elements without changing canonical plant topology.

### Data contract

Persist a versioned presentation document resembling:

```text
LayoutSchemaVersion
LayoutId
WorkspaceId / SchematicId
ElementOverrides:
    EquipmentId
    X
    Y
    optional presentation-only metadata
```

### Editing workflow

- explicit `EDIT LAYOUT` mode;
- drag selected element;
- optional snap/alignment aids;
- `LOCK LAYOUT`;
- `RESET TO DEFAULT`;
- optional save-as preset only if it remains presentation-only.

### Compatibility rules

- stable equipment IDs are the key;
- missing IDs from an old layout are ignored with diagnostic evidence;
- newly introduced equipment uses canonical default position;
- duplicate/invalid IDs fail safely;
- corrupt layout falls back to canonical defaults without affecting plant/session physics;
- layout schema changes are versioned.

### Tests

- round-trip layout persistence;
- old layout with removed element;
- layout with new plant element;
- corrupt/unknown schema handling;
- replay of plant state unaffected by layout file.

## M13.5 — Workspace presets

### Purpose

Give operators fast context setup without creating automation.

### Candidate presets

- STARTUP;
- SYNCHRONIZATION;
- NORMAL GENERATION;
- REACTOR TRANSIENT;
- TURBINE TRIP;
- ELECTRICAL EVENT;
- LOCA RESPONSE;
- POST-INCIDENT REVIEW.

### Presets may change

- selected workspace;
- viewport position/zoom;
- visible educational layer(s);
- expanded/collapsed presentation panels;
- selected trend sources;
- contextual tab/filter.

### Presets may not

- dispatch plant commands;
- change requested/effective authority;
- acknowledge alarms;
- clear trips;
- change challenge score/lifecycle;
- move plant components;
- inject faults.

### Tests

Apply preset to identical plant state and prove canonical plant snapshot unchanged.

## M13.6 — Real operating procedures

### Purpose

Replace/extend generic guidance with structured procedures grounded in canonical commands and evidence.

### Procedure step contract

Each step should define:

- stable procedure/step ID;
- operator-facing instruction;
- prerequisite evidence;
- expected/allowed canonical command(s);
- completion evidence;
- hold/warning evidence;
- optional failure/escalation note;
- optional navigation target;
- provenance/reference note where educationally useful.

### Initial procedure families

Start from already validated operational content:

- cold-shutdown/pre-start alignment;
- first criticality/low-power preparation;
- heat-up/steam raising/turbine startup;
- synchronization and initial loading;
- normal power manoeuvre;
- normal shutdown;
- selected generator/turbine trip recovery;
- selected fault response supported by current physics.

### Authority rule

Procedures guide and evaluate. They do not directly write physical outcomes and do not become a parallel command dispatcher.

### Replay/checkpoint

Procedure progress must be derivable from canonical actions/evidence or explicitly persisted in a deterministic versioned application contract.

## M13.7 — Instructor / Fault mode

### Purpose

Provide a deliberately separate training-authority surface for deterministic fault injection.

### Visual distinction

Instructor mode must be unmistakable through label, frame/palette/iconography and explicit armed state. It must never look like a normal operator panel.

### Authority contract

Instructor may:

- arm/select supported fault definitions;
- schedule/trigger deterministic faults through the canonical fault framework;
- inspect fault state/evidence;
- reset only faults whose owning model explicitly supports reset.

Instructor may not:

- write arbitrary plant state;
- create damage mechanisms not modeled yet;
- bypass protection ownership;
- masquerade fault commands as operator actions.

### Recorder/replay

Every instructor action must be visible in deterministic recording/session/replay evidence with separate provenance from operator actions.

## M13.8 — Integrated UX closure

### Automated

- workspace/preset plant-state invariance;
- maintained-handle replay semantics;
- layout round-trip/version handling;
- instructor action provenance;
- no UI project physics dependencies;
- ordinary suite.

### Manual

- keyboard-only operation;
- minimum supported window;
- mimic zoom/pan/fit/reset;
- layout edit/lock/reset;
- visual consistency of adopted controls;
- procedures usable without hidden mouse-only affordances;
- Instructor/Fault mode unmistakable;
- save/reload restores intended presentation state.

### Exit condition

M13 closes only when the improved control-room experience remains a consumer/dispatcher at existing boundaries and no feature requires Avalonia to own physical truth.
